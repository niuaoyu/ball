# tactic-lab sync · 使用说明

一条命令，把本地片段库同步到云端：

```
你在豆包版工具里标注保存（I/O + 标签 + 备注）
        ↓ 片段落盘到 Downloads/clips/（视频 + meta.json）
node sync.js          ← 就这一步
        ↓ 视频上传 Cloudflare R2（只在需要时）
        ↓ 元数据 upsert Supabase（改标签只更新这里，视频不动）
在线库刷新即可见
```

## 微博 / 腾讯标记 → 队列 → 上线（完整流程）

在微博或腾讯视频页装好油猴脚本（weibo-clipper）后，看到精彩回合：

```
微博页面：I 设开始 → O 设结束 →（可选 P 预览循环）→ 敲标签 → Enter 入队
电脑：    node import.js --queue     ← 只下载片段涉及的字节（十几秒片段≈1-4MB）
          node sync.js               ← 上线，手机刷新在线库
```

- 队列表是 `pending_imports`（Supabase），只存「来源 + 视频页地址 + 起止秒 + 标签」，**存的是页面地址不是 m3u8 直链**，避免临时流地址过期
- 腾讯暂时支持单视频页面；合集 / 多集页面先不要入队
- `--queue` 消费规则：新条目→裁剪落盘；处理过但没标记成功的→补标记不重复下载（本地台账 `.import-ledger.json`）；失败的→标记 failed 并显示原因
- 裁剪参数：`--download-sections` + `--force-keyframes-at-cuts`（帧级精确重编码）+ faststart（moov 在头部，网页秒开可拖动）
- 队列模式清晰度默认 720p，可 `node import.js --queue 480` 改 480
- **标记时记得敲标签**再按 Enter，否则在线库里显示「无标签」（事后可改 meta.json 重跑 sync）
- 首次使用需在 Supabase SQL Editor 跑一次 `pending-imports.sql` 建队列表

## 微博 / 腾讯视频导入（import.js）

看到微博或腾讯视频上的比赛视频想标注？先把它下载到本地，再走正常流程：

```
node import.js http://t.cn/AXWUrOoN          # 微博，默认 720p
node import.js http://t.cn/xxxx 480          # 微博，指定清晰度：480 / 720 / 1080
node import.js https://v.qq.com/x/cover/mzc00200ylcvbyu/s4102x4spyo.html 720  # 腾讯单视频页
```

- 微博接受：`t.cn` 短链、`weibo.com/tv/show/1034:xxx`、`video.weibo.com/show?fid=1034:xxx`
- 腾讯接受单视频页：`v.qq.com/x/cover/.../*.html` 或 `v.qq.com/x/page/.../*.html`
- 视频下载到 `Downloads/videos/`，旁边自动生成 `.meta.json` 记录来源（原链接、上传者、时间），方便日后追溯
- 腾讯页面标题偶尔无法由 yt-dlp 提取，但不影响视频下载；会使用视频 ID 作为兜底标题
- 依赖：`yt-dlp` + `ffmpeg`（一次性安装，管理员 PowerShell 执行）：

```powershell
winget install yt-dlp.yt-dlp
winget install yt-dlp.FFmpeg
```

- 已实测：1.23GB 的 113 分钟视频 3 分钟下完（约 7MB/s），h264+aac 格式浏览器直接兼容
- 下载完成后：在本地 tactic-lab 里打开这个视频 → 标注裁剪 → `node sync.js` 上线

**版权注意**：微博视频下载仅供个人学习研究；在线库是公开页面，不要大量搬运他人视频内容。

## 首次使用（只做一次）

### 1. 填密钥

打开本目录的 `.env`，只填 3 个空：

| 键 | 去哪里拿 |
|---|---|
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | Cloudflare 控制台 → R2 → 右上 **Manage R2 API Tokens** → Create API Token（权限选 Object Read & Write、指定 bucket `ball`）。Secret 只显示一次，注意保存 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API → **service_role** 那把（anon/publishable 旁边的） |

其他值已填好。**这三个都是机密：只待在这个文件里，不进聊天、不进 Git（.gitignore 已配好）。**

### 2. 测试

```
node sync.js --dry-run
```

预演模式只读不写，不需要密钥也能跑。它会列出每个片段会被怎么处理（新增 / 重切 / 更新 / 无变化）。

### 3. 正式同步

```
node sync.js
```

## 日常使用（标注 → 上线，两步）

1. 在豆包版工具里看球、`I`/`O` 标片段、打标签、保存（工具自动落盘）
2. 命令行 `node sync.js`，完事手机刷新在线库

## 同步规则（幂等，随便重跑）

| 本地相对云端 | 动作 |
|---|---|
| 新片段 | 上传视频 + 写数据库 |
| 起止时间 / 时长变了 | 重新上传视频 + 更新数据库 |
| 只有标签 / 备注变了 | **只更新数据库，视频不重传**（几秒完成） |
| 完全没变 | 跳过 |
| 云端有、本地没有 | 只提示，不删（防误删） |
| R2 已有同名对象 | 跳过上传，不重复占用空间 |

## 在其他电脑上从零搭建（换机 / 新环境）

整个 sync 只依赖 **Node.js**（一个命令行运行时），不依赖 ffmpeg、不依赖数据库。新机器按下面四步走，约 10 分钟。

### 第 1 步：安装 Node.js（LTS 版，18 及以上）

三种方式任选其一：

**方式 A：官网安装包（最简单，适合所有系统）**

到 https://nodejs.org 下载 **LTS 版**（目前是 22.x，18 以上都行），双击安装，一路默认。装完打开终端验证：

```
node -v
npm -v
```

两条都能输出版本号（如 `v22.x.x`）即成功。

**方式 B：Windows 用 winget（免下载）**

管理员 PowerShell 里执行：

```powershell
winget install OpenJS.NodeJS.LTS
```

装完**重开终端**再验证 `node -v`。

**方式 C：macOS / Linux 用包管理器**

```bash
# macOS（有 Homebrew）
brew install node@22

# Ubuntu / Debian
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
```

> 为什么要求 18+：脚本用到的 `fetch`、ESM 等特性是 Node 18 起内置的；`@aws-sdk/client-s3` 也只承诺支持 16+。用 16 及以下会直接报错。

### 第 2 步：拷贝项目文件

把 `sync` 文件夹整个拷到新电脑（U盘 / Git / 局域网都行）。**`node_modules` 不用拷**（体积大且和系统相关），**`.env` 不建议随项目拷**（里面有密钥，走安全渠道单独传，或者到新机器重新填）。

最简清单只有 3 个文件：

```
sync/
├── sync.js        # 主脚本
├── package.json   # 依赖声明
└── .env           # 配置（新机器上重新填，见第 4 步）
```

（`.env.example` 是模板，忘了格式就抄它）

### 第 3 步：安装依赖（一次性）

在 sync 目录里执行：

```
npm install
```

会根据 package.json 下载 `@aws-sdk/client-s3`（约 20 MB，几十秒）。完成后目录里出现 `node_modules/`。**这一步不需要任何密钥**。

### 第 4 步：配置并验证

1. 复制 `.env.example` 为 `.env`（如果没有现成的），填 3 个空：两把 R2 密钥 + Supabase service_role key（见上文「首次使用」的表格）
2. 核对 `CLIPS_DIR`——新电脑上片段库路径多半不一样，改成实际路径（Windows 写法如 `C:/Users/你的用户名/Downloads/clips`）
3. 跑预演验证：

```
node sync.js --dry-run
```

能正常列出每个片段的处理计划（新增 / 无变化 / 更新），说明环境搭建完成。

### 平台差异备忘

| 系统 | 注意点 |
|---|---|
| Windows | 用 PowerShell 或 Git Bash 都行；路径正反斜杠都可以，`.env` 里建议用 `/` |
| macOS | 若提示 `command not found: node`，重开终端或检查 PATH |
| Linux | 不要用 `sudo apt install nodejs`（Ubuntu 仓库里的是老版本），用上面 NodeSource 方式 |

## 常见问题

- **`找不到片段库目录`**：改 `.env` 里的 `CLIPS_DIR` 指向你的片段库文件夹
- **`Supabase 写入失败 401/403`**：service_role key 填错了或用了 publishable key
- **R2 报 NoSuchBucket**：`.env` 里 `R2_BUCKET` 桶名不对（当前是 `ball`）
- **以后换电脑**：见上面「在其他电脑上从零搭建」——拷 3 个文件、`npm install`、重填 `.env`，即可
